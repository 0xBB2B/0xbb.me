# HD-2D 横版探索个人主页

## 1. 背景

访客需要通过操控主人公、沿道路探索并与 NPC 交谈，认识 FUBUKI_BB 的背景、技能和作品。当前没有现行规范覆盖这一体验，需要先建立明确、可验收的行为基线，避免将普通网页装饰成游戏或在方向未验证时铺满场景。

本次按需求变更建立新需求包，不是既有游戏故障修复。需求按里程碑实施，当前进入 M1 规划与实现；文档确认不代表产品已经实现或完成黑盒验收。

## 2. 目标与非目标

### 非目标

- 本轮执行到 M1 可玩样板为止，不实施 M2/M3，不推送或发布；不新增未经批准的依赖。允许相关代码、配置、测试和文档修改，以及通过验证后的本地提交。
- 不加入战斗、死亡、必须跳跃的障碍、背包、任务树、音频、后台服务、鼠标点击地面寻路或跨刷新存档。
- 不升级现有依赖，不改造部署平台，不制作原画级动画，不因没有测量依据的猜测进行性能重构。

### 目标

- 交付 3 个连续场景：黄昏城镇、科技工坊、星夜展街，分别通过 NPC 介绍个人背景、6 项技能与 3 个作品。
- 提供 1 位依据人物设定图用代码绘制的全身像素主人公，待机、行走、转向均由代码驱动；桌面键盘与手机触屏均可完整探索。
- 主人公、NPC、背景、道具、特效、头像、图标和交互 UI 全部代码化，成品位图素材数量为 0；允许程序化图形和纯矢量 SVG。
- 提供中文与英文 2 种界面及介绍，以及覆盖相同资料的速览入口；图形故障不阻断获取资料与外链。
- 在 1440×900、390×844、844×390 三种视口验证布局和操作；桌面记录设备与浏览器，连续测量 30 秒，目标 60 FPS，帧间隔 P95 不超过 33.4 ms。

| 里程碑 | 交付与验证 | 停止点 |
|---|---|---|

## 4. 边界与已知坑

### 授权与阶段门禁

- USER-013 已确认规范并授权规划、M1 工作流和对应本地提交；USER-011 的全站代码化与非发布参考材料边界继续适用。不得因规划包含后续里程碑就执行 M2/M3。产品验收状态由全部任务及黑盒验收门禁决定。
- 规则文件是产品行为事实源；此处只记改动目的、工程边界和交付门禁，不替代逐条验收。planner 应产出符合约束的任务集，明确标注 M1、M2、M3 分组与 M1 停止点；里程碑占位本身不可派工。
- 按任务使用 workflow 严格执行测试、实现、审查与验证，只有通过对应门禁才能提交。M1 的用户视觉确认是额外门槛，不能用自动测试通过替代。
- 性能改动须附测量环境、未达标指标、定位证据和改动后的同条件结果；缺少任一项不开展性能专项重构。M1 美术不通过时先修样板，不扩建后再重做。

### 已确定的规划边界

- AI-002、AI-003 已由主 agent 取得决策回执；planner 按下列架构与验证边界落盘任务，不需要对子任务编号、常规函数命名或既定职责内的机械拆分重复记录决定。
- 资料层：`data.ts` 管理中英个人事实，`portfolio/copy.ts` 管理界面词条，不依赖图形运行时。
- 交互层：`portfolio/state.ts` 与 `portfolio/input.ts` 管理移动、阅读、语言、输入释放和焦点中断，公开接口可由 Bun 行为测试调用，不嵌入渲染或静态页面内容。
- 图形层：`portfolio/geometry.ts` 与 `portfolio/character.ts` 用程序化几何构造像素形体并通过肢体分组变换实现动画；`portfolio/world.ts` 与 `portfolio/runtime.ts` 负责场景组合、相机、光照及图形生命周期。
- 界面层：`components/portfolio/` 下按 WorldViewport、Hud、Dialogue、Overview 分组件，组件样式由同一任务负责；`App.tsx` 只组合主页，`index.css` 负责基础样式。无须新状态库、游戏引擎或 UI 库。
- 场景层：`portfolio/scenes/` 的场景模块分别拥有布景、NPC 和中英台词。使用现有 Vite 的静态模块发现能力收集场景；M1 只有 town，M2 才添加 workshop/gallery，不预制未来场景或空实现，也不要求跨任务改写同一入口文件。
- 发布边界：素材发布配置、页面模板、元数据与参考图迁移分别明确列入文件归属；M1 只做样板可运行与无位图所必需的变更。M3 的整体清理须列出确切文件，不能用脚本掩盖大批未声明的源码改动。
- 验证组织：生产模块旁使用 `.test.ts` 或 `.test.tsx`；状态、几何和内容验证调用公开接口，React 静态输出可使用现有 `react-dom/server`。交互、画面、故障和视口使用 ego-browser 真实浏览器，不新增测试依赖，不以源码字符串检查替代行为证明。
- 文件归属：每个生产文件和测试文件均只有一个任务负责；全部 40 条验收需有任务映射，但 M1 的样板测试不代表三场景或发布验收已通过。每个任务仍须满足生产文件 ≤2、refs ≤3，所有删除文件也必须明确归属。
- 任务文档长度：按 USER-015，每个 `tasks/NN-*.md` 文件的完整内容 ≤200 行，包括 frontmatter、标题、正文、空行和代码块；该上限只针对任务文档，不限制任务修改的代码量，也不要求代码行数额度、删除豁免或新增/删除行数估算。任务规模由职责、文件归属、验收覆盖和 TDD 门禁控制。本次只修正当前需求，不修改共用 skill 或外部仓库。
- 如需增加上述边界之外的新架构、依赖或授权范围，planner 先返回具体的未定案提议，由主 agent 决策并取得回执后再写盘；若硬约束存在冲突，返回确切冲突文件、验收与拆分建议，不伪造可执行计划。

### 数据、素材与部署

- 当前事实来源为 `data.ts`：FUBUKI_BB 简介、6 项技能、3 个 ONLINE 作品、4 个社交入口。只翻译与调整叙述视角，不增加未经确认的个人经历；站点自身作品介绍随新体验更新。
- `public/profile-full.png` 实测为 1696×2528 的 RGB PNG，带背景且缺完整腿脚，仅作角色设计参考。实施时移出发布目录，不删除、不覆盖原图，不将其作为纹理、头像或任何运行素材。
- 全部成品图形由 SVG、CSS、程序化几何或绘制代码实现，动画由代码驱动；像素仅指画风，不表示必须使用位图精灵表。禁止 PNG、JPEG/JPG、WebP、GIF、BMP、AVIF、TIFF 等位图素材，也禁止 Base64 位图、伪装扩展名或 SVG 内嵌位图。
- 浏览器或图形引擎正常的屏幕栅格化不视为位图素材。原始设计参考和测试截图可以作为非发布材料存在，但不得进入构建产物、成为页面图形引用或作为 UI 素材；无图形网络请求也不能代替对内联内容的检查。
- 采用已选定的像素角色加立体场景路线，计划使用现有 React、Vite、Three.js 与 Bun 工作流；开源库及已有能力优先，不自行搭建通用游戏引擎，不新增未经批准的依赖。
- 后续移除范围包括旧 HUD 首页及其专属样式、光剑 `game/` 与 `components/beat-saber/`、专属音频和失去引用的依赖、游戏构建入口及元数据分支；只清本次替换产生的残留，不波及无关工具。头像、图标及分享图形引用须满足同一代码化约束，原始人物设定图按非发布参考处理。
- 仍为无账号的单访客浏览器体验，无服务器数据写入或多人同步。部署继续使用现有纯静态站点方式，不调整平台。
- 外链验收核对目标地址及浏览器导航行为，不把第三方网站可用性作为本站能够保证的结果。

### 失败与测量

- 加载中允许进入资料速览；必要图形或角色资源报错、图形不支持时展示故障说明与资料，不使访客只能等待。恢复可由访客刷新页面触发，不引入后台服务或自动重试系统。
- 首次默认英文，语言切换不重置位置或当前对话段落；刷新从起点及默认语言开始，不承诺跨刷新恢复。
- 记录实测设备、操作系统、浏览器版本和视口。桌面性能采样在加载结束、页面可见且连续行走期间持续 30 秒；包含跨场景时的帧间隔，不把加载时间或手机模拟当作真机性能数据。
- 390×844 与 844×390 的视口模拟仅验证布局及触屏交互。手机真机性能尚无设备和实测证据，不作为已完成项，也不得在发布报告中冒充已验证。
