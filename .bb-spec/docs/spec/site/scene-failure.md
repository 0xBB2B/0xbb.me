# 三维失败时的处理

## 目的
即使访客的浏览器跑不动三维画面，也能立刻读到完整个人资料并打开链接。

## 逻辑
- 以下三种情况都算三维失败：
  1. 三维画面所需的代码加载失败；
  2. 创建 WebGL 失败；
  3. 运行中 WebGL 上下文丢失。
- 发生任一失败时：
  - 加载页立即从页面移除；
  - 三维画面区域隐藏，背景显示深蓝径向渐变；
  - 页面直接进入资料视角（`data-view="story"`），显示小票，小票出现时同样从上方掉下来；
  - 小票上方显示一行提示：中文「3D 场景无法加载」，英文 "The 3D scene couldn't load"；
  - 小票、全身照相片、右上角语言开关都照常可用。
- 失败后不显示「返回全景」按钮，按 Esc 也不退出，页面一直保持资料视角。
- 访客正在资料视角读小票时发生失败：小票保持不动，出现失败提示，其余不变。
- 失败后不自动重试。

## 约束
- 三种失败都使 `data-view` 为 `story`，且加载页已从 DOM 移除。
- 失败提示文字与上文一致（中英文）。
- 失败后小票内容完整可读，四个链接可点击，点头像能弹出全身照相片。
- 失败后没有可见的返回按钮，按 Esc 后 `data-view` 仍为 `story`。
- 失败后页面中没有可见的 canvas。

## 例子
- 一位访客的浏览器禁用了 WebGL：加载页一闪而过，深蓝背景上掉下一张小票，上方写着「3D 场景无法加载」；他点 GitHub 链接，在新标签页打开。
- 另一位访客正在资料视角读小票时显卡驱动重置导致上下文丢失：身后的街景消失变成深蓝背景，小票上方出现失败提示，他继续往下读，不受影响。

## 验收
- [ ] 拦截三维代码请求：加载页移除，`data-view="story"`，小票可见，出现失败提示。
- [ ] 让 `getContext` 返回 `null`：结果同上。
- [ ] 就绪后调用 `WEBGL_lose_context.loseContext()`：结果同上，canvas 不可见。
- [ ] 失败后四个链接都存在且可点击，点头像弹出全身照相片。
- [ ] 失败后没有可见的返回按钮，按 Esc 后 `data-view` 仍为 `story`。
- [ ] 资料视角下触发上下文丢失：失败提示出现，小票层滚动位置不变。
