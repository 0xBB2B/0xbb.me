# 三维失败时的处理

## 目的
即使访客的浏览器跑不动三维画面，也能立刻读到完整个人资料并打开链接。

## 逻辑
- 以下三种情况都算三维失败：
  1. 三维画面所需的代码加载失败；
  2. 创建 WebGL 失败；
  3. 运行中 WebGL 上下文丢失。
- 发生任一失败时：
  - 加载页立即从页面移除；
  - 三维画面区域隐藏，背景显示深蓝径向渐变；
  - 页面直接进入资料视角（`data-view="story"`），停在第 1 段起点；
  - 第 1 段上方显示一行提示：中文「3D 场景无法加载」，英文 "The 3D scene couldn't load"；
  - 资料段、进度点、语言开关都照常可用，滚动照常吸附到各段起点。
- 失败后滚到顶不会回到整体视角，页面一直保持资料视角。
- 访客已经通过加载页的「先看资料」进入资料视角后才发生失败：同样显示失败提示，其余不变。
- 失败后不自动重试。

## 约束
- 三种失败都使 `data-view` 为 `story`，且加载页已从 DOM 移除。
- 失败提示文字与上文一致（中英文）。
- 失败后资料段 3 段内容完整可读，链接可点击。
- 失败后滚到顶 `data-view` 仍为 `story`。
- 失败后页面中没有可见的 canvas。

## 例子
- 一位访客的浏览器禁用了 WebGL：加载页一闪而过，直接看到深蓝背景上的第 1 段，上方写着「3D 场景无法加载」，下面是头像和 FUBUKI_BB；往下滚能看到简介和链接。
- 另一位访客在加载中点了「先看资料」，正在读第 2 段时显卡驱动重置导致上下文丢失：第 1 段上方出现失败提示，他继续往下读，不受影响。

## 验收
- [ ] 拦截三维代码请求：加载页移除，`data-view="story"`，出现失败提示。
- [ ] 让 `getContext` 返回 `null`：结果同上。
- [ ] 就绪后调用 `WEBGL_lose_context.loseContext()`：结果同上，canvas 不可见。
- [ ] 失败后 3 段内容与四个链接都存在且可点击。
- [ ] 失败后滚动到 0，`data-view` 仍为 `story`。
- [ ] 先点「先看资料」再触发失败，失败提示出现，滚动位置不变。
